Backend · FastAPI · OpenAI 相容 API Gateway · Runtime Plane 核心
Xparse 平台所有 LLM 推論的核心閘道。每個請求的處理流程：①向 IAM 驗證 API Key 取得 AuthContext（含解密的 Provider Key）→ ②向 Resource Manager acquire slot → ③透過 xparse_routing 決定路由策略 → ④StreamingManagerV3 呼叫 LLM Provider。支援 SSE 串流、Embeddings、TTS/STT、Agent Framework (v2 tasks)、能源感知品質閘門（QualityGate ~60% 節能）。
主要 API 端點
POST /v1/chat/completions (SSE) POST /v1/embeddings POST /v1/audio/speech GET /v1/models POST /v2/tasks POST /v1/signals/{id} GET /health GET /metrics (Prometheus)
依賴服務
xparse_iam (每次請求驗證) xparse_resource_mgr (slot) xparse_routing (in-process) NeMo Guardrails (安全) LLM Providers (推論) Redis (佇列/配額) xparse_audit (SDK+JSONL)
xparse_iam
:8010
Backend · Django Ninja · Governance / Control Plane 核心
平台的身份驗證與授權中心。管理 Tenant、Application、Group、API Key、Model Catalog、Provider Credentials（加密儲存）、Policy。API Key 三層查找（TenantKey → GroupKey → AppKey），SHA-256 雜湊不入庫。Provider Key 以 Master Secret + KEK 加密，在 /internal/gateway-validate 中解密後傳給 Gateway。支援 OIDC SSO（Keycloak）。
關鍵端點
POST /iam/internal/gateway-validate GET /iam/internal/node-allocations GET /iam/internal/group-quotas/{uuid} POST /iam/bootstrap POST /iam/oidc/exchange POST /iam/applications/{uuid}/deploy
依賴服務
Keycloak (OIDC JWKS) xparse_scheduler (觸發部署) xparse_fleet (sidecar/endpoint)

:8001
Backend · FastAPI · Audit & Observability · Clean Architecture
治理級審計基礎設施。核心原則：非阻塞（背壓滿時丟棄，主請求不等待）、Trace-first（所有事件綁定 trace_id）、僅附加不可變（不可修改或刪除歷史事件）、Schema 版本化。bustream 透過共享 JSONL 檔案（bind mount）寫入，同時 xparse_resource_mgr 透過 Python SDK 寫入。支援 Evidence Package 打包（ZIP）下載供合規用途。
主要 API
GET /events (含篩選) GET /events/trace/{traceId} GET /stats/summary GET /stats/top-applications POST /evidence/packages GET /diagnostics/store
寫入方

xparse_resource_manager
:8020
Backend · FastAPI · Endpoint Capacity Plane
管理共享推論端點的並發 Slot。Gateway 每次推論前必須 acquire 一個 lease，推論完成後 release，防止端點被超量並發壓垮。佇列為 min-heap（priority ASC + enqueue_ts ASC），TTL Reaper 背景任務定期回收過期 lease。request_id 冪等保護。
主要 API
POST /resource/endpoints/{id}/acquire POST /resource/endpoints/{id}/release GET /resource/endpoints/{id}/status PUT /resource/endpoints/{id} (Admin)
調度 · 編排層
xparse_scheduler
:8030
Backend · FastAPI · Workload Placement Scheduler
工作負載放置調度器。三階段演算法：① 向 IAM 查詢資源需求（resource-profiles）→ ② 向 IAM 驗證 Group 配額（group-quotas）→ ③ MostRemainingStrategy 選出最佳節點（五維資源向量：CPU/Memory/Disk/GPU/Container）。向 Fleet 下發部署命令後，等待節點心跳中繼確認（PENDING → ACTIVE 狀態轉換）。
主要 API
POST /scheduler/placements DELETE /scheduler/placements/{uuid} POST /scheduler/placements/{uuid}/restart GET /scheduler/capacity/nodes GET /scheduler/capacity/groups/{uuid}/usage
xparse_fleet
:8090
Backend · FastAPI · Orchestration Control Plane
GPU 節點群的編排控制平面（唯一可信狀態來源）。維護所有節點從 REGISTERED → ACTIVE 的完整狀態機（9 種狀態）。透過心跳 ACK 中的 pending_commands 向節點下發命令（部署/驗證/停止）。管理 GPU VRAM 感知放置、Port 分配登錄（bind mount 確保一次精確）、模型 Catalog 協調（L1 YAML → L2 IAM DB）。
主要 API
POST /v1/fleet/heartbeat POST /v1/fleet/deploy POST /v1/fleet/apps/{code}/deploy GET /v1/fleet/status POST /v1/fleet/nodes/{id}/approve GET /v1/fleet/routable-endpoints
節點層
xparse_node_mgr
:8080
Backend · FastAPI · Node Runtime Agent (agentd) · 掛載 Docker Socket
GPU 節點端的輕量控制平面（agentd）。掛載 host docker socket 管理本地容器。週期性向 Fleet 發送心跳（含服務狀態、GPU 用量、命令執行結果），接收回傳的 pending_commands 並執行（deploy/stop/validate 等）。Watchdog 監控 vLLM 實例健康，暫態失敗自動重啟，CUDA OOM 等永久錯誤不重試。狀態以 state.json（filelock + temp-rename 原子寫入）持久化。
主要 API
POST /v1/services/apply (vLLM) POST /v1/sandboxes POST /v1/sandboxes/{id}/exec POST /v1/models/download GET /v1/gpu/info GET /livez (Docker HEALTHCHECK)
Python Library（進程內，無 HTTP Port）
xparse_routing
Library · 被 bustream Gateway 引入 · 決定路由策略
為每個聊天請求決定使用哪些 LLM 模型、以何種模式執行（direct 單模型 / twin 雙模型）。策略設定以 SQLAlchemy 持久化（SQLite/PostgreSQL），60s TTL 快取避免頻繁查詢。決策日誌非同步 fire-and-forget 寫入，不影響回應延遲。5 種內建策略。
5 種路由策略
none → DirectStrategy (models[0]) smart_routing → TwinStrategy cost_first → 最低估算費用 energy_first → 最低焦耳/token health_aware → 健康分數優先
xparse_container_platform
Library · Clean Architecture · 被 xparse_node_mgr 引入
Sandbox 容器完整生命週期管理。Clean Architecture 嚴格分層（Domain → Ports → Infrastructure），DockerRuntime 透過 aiodocker 連接 Docker Engine Unix Socket。硬性安全約束（ADR-103）：硬碼 Privileged=False、CapDrop=ALL、ReadonlyRootfs、no-new-privileges，任何 privileged 請求在 schema 層以 422 拒絕。支援 Google nsjail per-execution 二次沙箱隔離。
