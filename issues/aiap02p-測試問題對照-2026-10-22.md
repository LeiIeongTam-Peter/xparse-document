## 各區塊細節

### LLM Proxy

- **`/v1/responses` 500（#1）**
  - `stage_errors.py:14` 的 `policy_evaluation_failed()` 包住 `request_policy`、`addressing`、`routing`、`policy_kernel` 四個 stage 的所有未預期例外，回應裡看不出是哪一個。
  - 它會 print `[Gateway] Policy evaluation error: <例外>`，抓這一行就知道原因。
  - 已排除 #6489（地端模型沒有 credential）：那個錯誤是 `credential_resolution_failed`，發生在 kernel 之後，訊息對不上。
  - 本地兩種 routing 模式都是 200，所以 main 上沒有這個問題。
- **gpt-6-luna（#2）**：本地 6 個面全部 200。tools + 預設推理的組合，gateway 會自動轉到 `/v1/responses`，log 有 `D10 ... surface_bridge`。
- **gemma（#4–#7）**
  - 直接打 vLLM（不經 gateway）：不帶參數時 content `''`、reasoning 392 字。帶 `enable_thinking=false` 時沒有 reasoning，但思考過程全部寫在 content，最後才給答案。
  - 所以這是 vLLM 設定和小模型本身的行為。換 gateway 版本只能讓 `reasoning_effort: none` 生效，而且要先把 gemma 登記成 `supports_reasoning=true`。
  - opencode、Codex 都不帶 `reasoning_effort`，改了也救不了它們的空白回覆。
- **（新發現）haiku 在 `max_tokens` 很小時也會空白**：`max_tokens=120` 問「什麼是集保帳戶？」，有一次 119 個 token 全花在 thinking，content 空白、`finish_reason=length`；改成 1000 就正常。不是 bug，但 client 設很小的上限時會看到空白。

### Smart routing

- **分級對應（#18）**：本地 6 個候選時，SIMPLE（score 0.0）給 position 5，MEDIUM（0.15–0.19）給 position 4。chat 和 `/v1/responses` 的決策完全一樣。
- **heuristic 給分偏低**：我出的系統設計題和「step by step 證明 √2」都只判成 MEDIUM，沒到 COMPLEX／REASONING。所以排在 pool 前面的模型，平常幾乎選不到。這不是 bug，但會影響 pool 要怎麼排。
- **reliability（#19）**：`resolver.py:99` 只看 `hard_constraint_rate`。它只在「成功完成但輸出違規」時更新（`routes/chat.py:1203`、`responses_resilience.py:604`）。
  - gemma 常常空白輸出 → 被排除。
  - luna 每次都 400 → 從來不計入。
  - #6362 刻意讓「被拒絕的請求」不扣健康分。缺口是「設定錯誤、永遠 400 的模型」沒有任何機制會把它拿掉。
- **latency（#20）**：`_objective_pick.py:329` 每次決策只選一種訊號，取「每個有訊號的候選都有」的那一種。流量 EWMA 10 分鐘沒更新就失效（`:143`），重啟也會歸零。所以多數時候只剩 IAM probe 的 `last_latency_ms` 可比，而 probe 只代表連線速度，不代表推論速度。

### Budget

- **quota 設定和解除**：本地設定後 0.1 秒就擋、清掉 1.2 秒就放行。budget limit 也一樣：0.1 秒擋、刪掉 0.9 秒放行。
- **aiap02p 要等 30 秒（#22）**：IAM 的 `gateway_cache_evict.py:23` 只往 `XPARSE_GATEWAY_INTERNAL_URL`（預設 `http://xparse-scr:8000/v1`）推一次，失敗只記 warning。
  - 如果 aiap02p 的這個 URL 不對，或 gateway 有多個副本（只有一個收到），就只能等 TTL。
  - 驗證方式：在 IAM log 找 `validate-cache evict push failed`。
- **狀態碼（#23）**：#6367 把 quota／budget 的拒絕從 429 改成 400。aiap02p 升版後，看 429 判斷的 client 或監控要跟著改。
- **audit（#24）**：budget limit 擋下有 `audit.budget.exhausted`；interim quota 擋下的請求在 audit 查不到任何事件。

### Runtime／Audit
